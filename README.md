# Developer Workflow Toolkit

Early development (0.x). A reusable, provider-agnostic toolkit for validating AI-assisted software changes. The current development branch includes an evidence-checked semantic-review module, offline contract tests, versioned configuration validation, an allowlisted task runner, deterministic acceptance reports, and a reusable Python/Node acceptance workflow.

No credentials are committed. Offline tests do not establish live model behavior or guarantee complete defect detection. This branch is still under review; features here are not considered merged into `main` until the relevant pull requests are merged.

Start with [examples/harness-config.json](examples/harness-config.json); the opt-in model smoke test is documented in [docs/SEMANTIC_REVIEW_SMOKE_TEST.md](docs/SEMANTIC_REVIEW_SMOKE_TEST.md). See [docs/ROADMAP.md](docs/ROADMAP.md) for staged acceptance criteria, [docs/STABLE_ACCEPTANCE_CONTRACT.md](docs/STABLE_ACCEPTANCE_CONTRACT.md) for the current 0.x semantic-review contract, [docs/HARNESS_CONFIG_V1.md](docs/HARNESS_CONFIG_V1.md) and [docs/HARNESS_RUNNER_V1.md](docs/HARNESS_RUNNER_V1.md) for the fixed task allowlist and safe runner behavior, [docs/REUSABLE_ACCEPTANCE_WORKFLOW.md](docs/REUSABLE_ACCEPTANCE_WORKFLOW.md) for immutable SHA pinning, security boundaries, and upgrades, and [docs/DOCUMENT_PRECEDENCE.md](docs/DOCUMENT_PRECEDENCE.md) for resolving documentation conflicts and correcting stale content.
